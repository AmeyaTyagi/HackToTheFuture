# Photon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows and macOS tray app that recolors the whole screen for color blind users, with a judge view simulator, color names, a vision test and a conflict finder.

**Architecture:** An Electron main process owns settings, shortcuts, screen capture and a per-platform recoloring backend (Windows Magnification API, macOS capture-and-shader overlay). Renderer pages are served by Vite and reach the main process through a preload `photon` API. All color math lives in a pure `engine` module shared by both sides.

**Tech Stack:** Electron, Vite, plain JavaScript (ES modules), koffi, `node --test`, concurrently, wait-on, cross-env.

**Spec:** `docs/superpowers/specs/2026-10-03-photon-design.md`

**Execution note:** The human partner said "Start building", so this plan is executed natively in the authoring session. To avoid writing every file twice under a 24-hour deadline, tasks give exact files, interfaces, test cases and verification commands, and include code only where the wrong choice is easy to make. Commits are left to the human partner, who has not asked for any.

## Global Constraints

- App name: Photon.
- Vision type ids: `protan`, `deutan`, `tritan`, `achroma`. Severity is 0..1.
- Default settings: `{ "enabled": false, "type": "deutan", "severity": 0.8 }`.
- Shortcuts: `CommandOrControl+Alt+P` toggle, `+S` simulator, `+C` color names, `+F` conflict finder.
- Dev server: `http://localhost:5173`. `PHOTON_DEV=1` makes the main process load from it.
- `PHOTON_BACKEND=overlay` forces the overlay backend on Windows.
- `src/engine/` imports nothing from Electron or Node.
- Simulation matrices: Machado, Oliveira and Fernandes (2009), tabulated at severity 0, 0.5 and 1.0 and linearly interpolated between.
- Conflict thresholds: `deltaE > 20` in normal vision and simulated `deltaE < max(8, 0.35 x normal)`.
- Vision test: cone-isolating plates, a six-level ladder (deltaE 56, 40, 28, 20, 14, 10), one control plate plus a seven-plate staircase per axis. Tie order: deutan, protan, tritan. (Replaces the original three-plates-per-axis design; see the spec.)
- Color names: the label appears after the cursor rests for 3 seconds and hides when it moves.
- Apple-style interface: system font stack, translucent background, 12 px radius, light and dark themes.
- The screen must never stay recolored after the app exits.

## Review Focus

1. **Corrupt or hand-edited settings file** (severity `"abc"`, `5`, or type `"blue"`): the app starts with clamped or default values. Test in Task 2.
2. **Display scaling above 100%**: the cursor position is in logical pixels and the snapshot in physical pixels; color names must read the pixel under the cursor. Test of `toImagePoint` in Task 5.
3. **A screen that is one flat color**: the conflict finder reports no conflicts and does not crash. Test in Task 7.
4. **Empty or non-digit vision test answers** (`""`, `"x"`, `null`): scored as a miss, never as an exception. Test in Task 6.
5. **Out-of-range colors after correction**: results clamp to 0..255 with no wraparound. Test in Task 1.

### Task 1: Engine

**Files:** Create `package.json`, `src/engine/{matrices,color,index}.js`, `tests/engine.test.js`.

**Interfaces (Produces):**
- `simulate(type, severity) -> number[9]` (row-major 3x3)
- `correct(type, severity) -> { matrix: number[9], offset: [r, g, b] }` (offset in 0..1 units)
- `applyMatrix(matrix, offset, [r, g, b]) -> [r, g, b]` integers, clamped 0..255
- `multiply(a, b) -> number[9]`
- `deltaE([r,g,b], [r,g,b]) -> number` (CIE76)
- `colorName([r,g,b]) -> string`
- `TYPES = ['protan','deutan','tritan','achroma']`, `IDENTITY`

- [ ] Write `tests/engine.test.js` covering: identity at severity 0 for every type; every row of every `simulate` matrix sums to 1 within 1e-4; `correct` at severity 0 leaves `[200, 30, 30]` unchanged; for `deutan` at 1.0 the pair `[200, 60, 40]` / `[110, 130, 40]` has a larger simulated `deltaE` after correction than before; same for `tritan` with `[60, 90, 200]` / `[60, 150, 120]`; `applyMatrix` with a matrix of all 2s clamps to 255 and with negative entries clamps to 0; severity outside 0..1 and `NaN` are clamped; `deltaE` of identical colors is 0 and of black/white is 100 within 0.5; `colorName` table: `[255,0,0]` red, `[120,0,0]` dark red, `[0,0,0]` black, `[255,255,255]` white, `[128,128,128]` gray, `[0,128,0]` green, `[0,0,255]` blue, `[255,255,0]` yellow, `[150,75,0]` brown.
- [ ] Run `node --test tests/` and confirm the tests fail because the modules do not exist.
- [ ] Implement `matrices.js`, `color.js`, `index.js`. Daltonization: `C = I + E (I - S)` with `E = [0,0,0, 0.7,1,0, 0.7,0,1]` for protan and deutan and `E = [1,0,0.7, 0,1,0.7, 0,0,0]` for tritan. Achroma: `simulate` blends identity toward Rec. 709 luminance rows `[0.2126, 0.7152, 0.0722]`; `correct` is contrast `k = 1 + 0.5 * severity`, matrix `k * I`, offset `0.5 * (1 - k)` per channel.
- [ ] Run `node --test tests/` and confirm all pass.

### Task 2: Windows correction, tray, panel, settings, toggle

**Files:** Create `vite.config.js`, `src/main/{main,settings,shortcuts,windows}.js`, `src/main/preload.cjs`, `src/main/backends/{index,magnifier}.js`, `src/renderer/index.html`, `src/renderer/shared/{apple.css,api.js}`, `src/renderer/panel/{index.html,main.js}`, `tests/settings.test.js`, `tests/magnifier.test.js`.

**Interfaces:**
- Consumes: `correct`, `TYPES` from Task 1.
- Produces: backend `{ start(), apply({matrix, offset}), clear(), stop() }`; `toMagMatrix(matrix, offset) -> number[25]`; `sanitize(raw) -> settings`; IPC channels `settings:get`, `settings:set` (partial settings in, full settings out), `settings:changed` (push), `action:run` (`'simulator' | 'names' | 'conflicts' | 'test'`); `window.photon = { getSettings, setSettings, onSettings, run, platform }`; `shared/api.js` default export is `window.photon` or the browser stub with the same shape.

Magnification API binding (transposed, because Windows multiplies a row vector `[r g b a 1]` by the matrix):

```js
const lib = koffi.load('Magnification.dll')
const MAGCOLOREFFECT = koffi.struct('MAGCOLOREFFECT', { transform: koffi.array('float', 25) })
const MagInitialize = lib.func('bool __stdcall MagInitialize()')
const MagUninitialize = lib.func('bool __stdcall MagUninitialize()')
const MagSetFullscreenColorEffect = lib.func('bool __stdcall MagSetFullscreenColorEffect(MAGCOLOREFFECT *effect)')

export function toMagMatrix(m, offset) {
  return [
    m[0], m[3], m[6], 0, 0,
    m[1], m[4], m[7], 0, 0,
    m[2], m[5], m[8], 0, 0,
    0, 0, 0, 1, 0,
    offset[0], offset[1], offset[2], 0, 1,
  ]
}
```

- [ ] Write `tests/settings.test.js`: `sanitize(undefined)` returns defaults; `{severity: 5}` gives 1; `{severity: 'abc'}` gives 0.8; `{type: 'blue'}` gives `deutan`; `{enabled: 'yes'}` gives `false`; valid input passes through.
- [ ] Write `tests/magnifier.test.js`: `toMagMatrix` of identity and zero offset is the 5x5 identity; element `[1][0]` of the result equals `m[1]` of the input; offsets land in row 4.
- [ ] Run tests, confirm failure, implement, confirm pass.
- [ ] Add scripts: `dev` = `concurrently -k "vite" "wait-on http://localhost:5173 && cross-env PHOTON_DEV=1 electron ."`, `build` = `vite build`, `start` = `vite build && electron .`, `test` = `node --test tests/`.
- [ ] Verify the binding outside Electron first: a one-off Node script that initializes, applies the deutan matrix, reads it back with `MagGetFullscreenColorEffect`, clears and uninitializes. Expected: every call returns true and the read-back matches.
- [ ] Implement main process, tray, panel. Single-instance lock. On `before-quit`: `clear()` then `stop()`.
- [ ] Run `npm run dev`. Expected: tray icon appears, panel opens, switch recolors the whole screen, Ctrl+Alt+P toggles, quitting restores the screen, `http://localhost:5173/panel/` renders in a browser with the stub banner.

### Task 6: Vision test

**Files:** Create `src/engine/visiontest.js`, `src/renderer/test/{index.html,main.js}`, `tests/visiontest.test.js`.

**Interfaces:** Produces `PLATES` (10 entries of `{ id, axis: 'control'|'protan'|'deutan'|'tritan', digit, background: rgb, figure: rgb }`) and `scoreTest(answers) -> { status: 'ok'|'none'|'invalid', type?, severity? }`, where `answers` maps plate id to the typed string or `null`.

- [ ] Test scoring: all correct gives `none`; control wrong gives `invalid`; two deutan misses give `deutan` 0.7; three tritan misses give `tritan` 1.0; one protan and one deutan miss gives `deutan` 0.4; answers `""`, `"x"` and `null` count as misses.
- [ ] Implement plates (figure and background colors chosen along each confusion axis with decreasing difference), the dot renderer with randomized brightness, and the result screen with Apply and the screening disclaimer. Correction pauses while the test window is open.
- [ ] Verify each plate against the simulator math: for its axis at severity 1, `deltaE(simulate(figure), simulate(background))` is small; in normal vision it is large. Add this as a test.

- [ ] Test: a half-and-half image of a deutan confusion pair yields one pair; red and blue yields none; a flat image yields none; an empty image yields none.
